# Demo-Kopien — kein Ergebnis der Skills

Die Dateien in diesem Ordner sind **Kopien der GitHub-Issues**, angelegt allein
für den Vortrag. Sie entstehen bei keinem Lauf der Engineering-Skills.

## Warum das hier steht

Mit einem konfigurierten GitHub-Tracker legen die Skills Spec und Tickets
**ausschliesslich** als Issues ab:

- `/to-spec` schreibt die Spec und publiziert sie in den Issue-Tracker.
- `/to-tickets` bietet ausdrücklich ein Entweder-oder — entweder lokale
  Markdown-Dateien unter `.scratch/<feature-slug>/issues/`, **oder** ein echter
  Tracker. Nicht beides.

Da `docs/agents/issue-tracker.md` auf GitHub zeigt, gilt der zweite Zweig. Ein
Ordner wie dieser würde also nie entstehen.

Er existiert, damit die Demo auch ohne Netz funktioniert und damit man Spec und
Tickets im Editor nebeneinander legen kann, statt zwischen Browser-Tabs zu
springen.

## Massgeblich sind die Issues

| Datei | Issue |
|---|---|
| `issue-01-spec-umsteigeverbindungen.md` | [#1](https://github.com/jbandi/agentic-sbb-example/issues/1) |

Die Tickets folgen im nächsten Schritt (`/to-tickets`), ebenfalls nur als
Issues.

Weichen Kopie und Issue voneinander ab, gilt das Issue. Kommentare, Labels,
Blocking-Kanten und der Status leben ohnehin nur dort — dieser Ordner hält bloss
den Text fest, wie er beim Publizieren aussah.
